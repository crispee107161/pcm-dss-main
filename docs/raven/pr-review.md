## Second pass: review of the fixes themselves (2026-08-21)

Per this project's "review uncommitted changes before commit" convention, ran `code-review-analyst` a second time — this time against the fix diff itself, not the original feature. Two real findings, both fixed:

- **H3's recorded justification was itself wrong.** The original write-up (above) only checked `spend > 0 AND results <= 0` (zero rows) and concluded per-row/post-aggregation filtering were equivalent. The reviewer caught that the *mirror* case, `spend <= 0 AND results > 0`, was never checked — and it isn't empty: 4 of 187 ads have a zero-spend tail month with a small positive `results` count, which per-row filtering silently drops. Verified independently against `lib/stats/__fixtures__/fr31-raw-ads.json`: real but immaterial (results off by 1–4, CPI off by <0.2% on 4/187 ads, `n` unchanged, no predictor affected — nothing moves at published-reference precision). Corrected the comment in `fr31-regression.ts` and this doc to state the true, asymmetric, immaterial finding instead of a false categorical equivalence claim.
- **`aria-label` on `StabilityPill`'s bare `<span>` was invalid** — ARIA 1.2 prohibits `aria-label` on role-less/generic elements, so the L-series a11y fix might have been a no-op for some assistive tech and a visible-label mismatch for others. Removed it; the visible footnote already added under the coefficient table is the fix that actually works for everyone, `title` stays as a mouse-hover bonus only.

Also picked up, all fixed: mismatched `M11`/`L5`/`L12` code-comment references (the doc never broke L1–L12 into individual items, so comments now say "L-series fix" instead of a number that doesn't resolve to anything); `InsufficientData`'s title promoted to `<h2>` for consistency with the other section headings; `RegressionSection.tsx`'s VIF tiles now iterate `FR31_PREDICTORS` instead of `Object.entries(primary.vif)`, removing an unnecessary cast and pinning display order; `toRegressionRunRow`'s `Extract<Fr31Result, {status:'ok'}>` simplified to the already-imported `Fr31Fit` (same type); `docs/PROGRESS.md`'s stale "291/291 (62 new)" test count updated; added a stronger raw-fixture test (`fr31-regression.test.ts`) asserting ad-for-ad numeric equality against the independently-frozen `fr31-secondary-187.json`, not just the observation count — verified to pass at zero relative difference, and would have caught the H3 gap above had it existed sooner.

**Judgment calls, not fixed (flagged by the reviewer as questions, not defects):**
- `fitFr31BothSpecifications` (the fit computation itself, not just its persistence) is unguarded by a try/catch in `loadRegressionAnalysis`. Confirmed unreachable today — the `n >= FR31_MIN_N` gate guarantees every downstream matrix operation has enough rows before any of the new empty-matrix guards could fire. Not adding a fallback UI/error-state for a path that's proven unreachable — that's exactly the speculative-code YAGNI warns against.
- The pre-existing, unrelated `correlationAssumptionRun.create()` in `loadAnalysisScreenData` (FR-21, not FR-31) has the same crash exposure H1 fixed for FR-31, but it's out of this diff's scope — left alone per the reviewer's own "fine to leave for a separate commit" framing.
- `mvp.md` §4.5A describes `MIN_SPEND_THRESHOLD_PHP` as "configurable"; the code exports it as a hardcoded constant. Doc/code mismatch, not a defect in current behavior — noted, not changed.
